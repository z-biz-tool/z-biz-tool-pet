## 1. Electron 三进程职责与安全边界

### 1.1 现状

| 进程 | 文件 | 职责 |
|------|------|------|
| Main | `src/main/index.ts`(1471行) + 11 模块 | 窗口管理、IPC、AI 路由、工具执行、养成/记忆/任务/成就/人设/场景/粒子、STT/TTS 子进程、托盘、快捷键、截图 |
| Preload | `src/preload/index.ts`(252行) | contextBridge 暴露 ~50 API |
| Renderer(pet) | `src/renderer/pet/App.tsx`(1456行) | 动画渲染、拖拽、语音录制/播放、情绪展示、**直接 fetch ollama**（越权） |
| Renderer(admin) | `src/renderer/admin/App.tsx`(1068行) | 对话管理、设置、会议、工具确认、**直接 fetch ollama**（越权） |

### 1.2 推荐职责边界

```
Main（唯一信任域）:
  ├─ 所有 AI 请求路由（统一 ai:chat / ai:streamChat）
  ├─ 所有文件系统访问（白名单限制）
  ├─ 所有 shell/命令执行（需确认 + 沙箱）
  ├─ 窗口/托盘/快捷键/系统交互
  ├─ 子进程生命周期（STT/TTS/ffmpeg）
  └─ 持久化（加密存储）

Preload（最小暴露）:
  ├─ 仅暴露 renderer 必需的 IPC invoke/send 包装
  ├─ 不暴露 Node API（fs/path/child_process）
  └─ 类型声明与实现严格一致

Renderer（纯 UI）:
  ├─ 禁止直接网络请求（fetch/axios 到外部服务）
  ├─ 所有数据通过 IPC 获取
  ├─ 动画/交互/状态展示
  └─ CSP 限制 connect-src
```

**关键改造**：
- 删除 pet/admin 中所有直接 `fetch(ollamaUrl)` 调用，统一走 `ai:chat` IPC（修复 D13/D14）
- 渲染进程添加 CSP meta：`<meta http-equiv="Content-Security-Policy" content="default-src 'self'; connect-src 'self'">`
- `file:read` 添加路径白名单（仅允许 `~/.z-bot/` 和 `app.getPath('temp')`）

## 2. Whisper 语音识别集成与性能

### 2.1 现状问题

- `whisper.cpp/` 目录为空：无模型、无编译产物（D21）
- `server/stt.js` 硬编码路径 `whisper.cpp/build/bin/whisper-cli` 和 `models/for-tests-ggml-tiny.bin`
- 每次请求 spawn 新 whisper-cli 进程（冷启动开销 ~500ms）
- 依赖系统 ffmpeg 做 webm→wav 转换（额外进程 + 磁盘 I/O）
- 无模型下载/版本管理机制

### 2.2 推荐架构

```
方案 A（推荐）：whisper.cpp 常驻服务
  ├─ 编译 whisper.cpp 为 server 模式（HTTP API）
  ├─ 启动时加载模型到内存（tiny/base 按需）
  ├─ 支持流式输入（PCM chunk → 实时转录）
  └─ 消除每次 spawn 冷启动

方案 B：faster-whisper Python 服务
  ├─ server/stt_faster.py 已存在（Flask + faster-whisper）
  ├─ 模型首次自动下载（HuggingFace cache）
  ├─ int8 量化 CPU 推理
  └─ 需管理 Python 依赖（pyinstaller 打包或内嵌）
```

### 2.3 模型管理

| 模型 | 大小 | 延迟(10s音频) | 质量 | 推荐场景 |
|------|------|---------------|------|----------|
| tiny | 75MB | ~0.5s | 低 | 开发/低配 |
| base | 142MB | ~1s | 中 | 默认 |
| small | 466MB | ~3s | 高 | 高质量需求 |

建议：首次启动引导下载 base 模型到 `~/.z-bot/models/`，支持设置切换。

### 2.4 STT 服务契约

```

  Body: { audio: base64 | file, format: 'webm'|'wav'|'pcm', language?: 'zh'|'auto' }

POST /transcribe/stream  (规划新增)
```

## 3. Server 服务架构

### 3.1 现状

- STT(:8084) 和 TTS(:8086) 为独立 Express 进程，由 main spawn
- 无鉴权、无 TLS、绑定 0.0.0.0（局域网可访问）
- 无健康检查、无自动重启
- TTS 依赖 Python + edge-tts（联网）

### 3.2 推荐改造

```
1. 绑定 127.0.0.1（仅本地访问）
2. 启动时生成随机 token，通过环境变量传递给 server 子进程
3. 所有请求校验 X-Auth-Token header
4. 添加 /health 端点，main 定期探活
5. 进程异常退出自动重启（最多 3 次，间隔递增）
6. TTS 替换为本地方案：
   - macOS: say 命令 / AVSpeechSynthesizer
   - Windows: SAPI5 / edge-tts 离线替代
   - 跨平台: Piper TTS (ONNX, 本地, 多语言)
7. 统一端口管理：STT/TTS 合并为单服务或动态端口分配
```

### 3.3 TTS 服务契约

```
POST /speak
  Body: { text: string, voice?: string, speed?: number }
  Response: { audio: base64, format: 'mp3'|'wav', duration_ms: number }
  Headers: X-Auth-Token: <local-secret>

POST /speak/stream  (规划新增)
  Response: Transfer-Encoding: chunked, audio/mpeg
  // 流式返回音频片段，首字节延迟 < 300ms

GET /voices
  Response: { voices: [{ id, name, language, gender }] }
```

## 4. 动画渲染性能与 CPU/内存

### 4.1 当前性能瓶颈

| 瓶颈 | 位置 | 影响 |
|------|------|------|
| 鼠标追踪 100ms IPC 轮询 | pet/App.tsx L252 | 每秒 10 次跨进程调用 |
| 贴墙动画主进程 setInterval 30ms | main/index.ts L652 | 阻塞主进程事件循环 |
| CSS 动画 540 行内联 style | pet/App.tsx L906-1450 | 首次解析开销、无缓存 |
| 双窗口始终运行 | admin + pet 同时存在 | 即使 admin 隐藏仍占内存 |
| 2 个 Express 子进程常驻 | STT + TTS | 各 ~50MB Node 运行时 |
| `--disable-gpu` 强制软件渲染 | main/index.ts L33 | CPU 渲染所有合成层 |

### 4.2 优化方案

**IPC 降频**：
- 鼠标追踪：改为主进程 `screen.on('mouse-moved')` 事件 push（macOS 需轮询但可降至 200ms），或仅在 pet 窗口可见时追踪
- 拖拽：使用 `-webkit-app-region: drag` 替代手动 IPC（Electron 原生支持）
- 贴墙动画：移至渲染进程 `requestAnimationFrame` + CSS transition，完成后 IPC 通知 main 最终位置

**GPU 恢复**：
- 移除 `--disable-gpu` / `--disable-gpu-compositing` / `--disable-software-rasterizer`
- 仅保留 `--disable-gpu-sandbox` 的替代方案（使用 `sandbox: true` 在 webPreferences）
- 透明窗口在 macOS/Windows 上 GPU 合成正常工作

**内存控制**：
- admin 窗口延迟创建（首次打开管理端时才 create）
- admin 隐藏时可选 `webContents.destroy()` 释放渲染进程（需权衡恢复速度）
- STT/TTS 按需启动（首次语音交互时 spawn，空闲 5 分钟后 kill）
- 目标：常驻内存 < 200MB（pet 窗口 + main 进程）

### 4.3 量化验收目标

| 指标 | 当前估计 | 目标 | 测量方法 |
|------|----------|------|----------|
| idle CPU | 3-8% | < 1% | Activity Monitor / Task Manager, 无交互 60s |
| idle 内存(RSS) | 300-500MB | < 200MB | `process.memoryUsage()` + 系统工具 |
| 拖拽帧率 | ~20fps(IPC瓶颈) | ≥ 55fps | Chrome DevTools Performance |
| 动画帧率(idle) | 未测 | ≥ 30fps | requestAnimationFrame 计数 |
| 启动到宠物可见 | 未测 | < 3s | 时间戳打点 |
| STT 冷启动 | ~500ms(spawn) | < 100ms(常驻) | 服务 /health 响应 |

## 5. 跨平台适配（macOS / Windows）

### 5.1 当前平台差异

| 功能 | macOS | Windows | 现状 |
|------|-------|---------|------|
| 截图隐身 | `setHiddenInMissionControl` + `setContentProtection` | 无实现 | D18 |
| 录音设备 | avfoundation | dshow | meeting-transcriber 已处理 |
| 全局快捷键 | Cmd+Shift+Z | Ctrl+Shift+Z | `CommandOrControl` 已处理 |
| 托盘图标 | 模板图像(16×16) | .ico(256×256) | 未确认图标资源 |
| 开机自启 | Login Items | Registry/Startup | 未实现 |
| 窗口透明 | 正常 | 需 `transparent:true` + 禁用 Aero | 未测试 |
| TTS | `say` 命令可用 | SAPI5 可用 | 当前用 edge-tts(联网) |

### 5.2 跨平台改造清单

1. **截图隐身**：Windows 用 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`（需 native addon 或 PowerShell 调用）
2. **开机自启**：`app.setLoginItemSettings({ openAtLogin: true, args: ['--minimized'] })`
3. **托盘图标**：准备 `icon.ico`(Win) + `iconTemplate.png`(macOS 16×16/32×32)
4. **窗口透明**：Windows 10+ 需确认 DWM 合成开启；添加 `app.disableHardwareAcceleration()` 降级选项
5. **本地 TTS**：macOS `say -v Ting-Ting`；Windows `Add-Type -AssemblyName System.Speech`；或统一 Piper
6. **路径分隔符**：检查所有硬编码 `/` 路径（server/stt.js 中 whisper 路径）
